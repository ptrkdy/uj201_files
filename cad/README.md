# CAD source

Produced by `tools/fusion/fusion_export_all.py`, which walks the active Fusion
project and exports every design in one run rather than one File → Export
dialog at a time. Point it at this directory.

    cad/source/   *.f3z    Fusion archives  — editable, Fusion only
    cad/step/     *.step   STEP             — the interchange format
    print/plates/ *.3mf    slicer projects  — arranged, printable

The exporter mirrors the project's folder tree, so move or flatten the results
as suits you; nothing downstream depends on the layout.

## Why three formats

**`.f3z`** keeps design history and bundles every referenced design, so one
archive of an assembly carries its components with it. It is the format to
come back to when editing. It is also the format nobody without an Autodesk
licence can open, which is why it is not the only one here.

**`.step`** is what makes this CAD genuinely reusable — FreeCAD, Onshape,
SolidWorks and most else read it. Published CAD without a STEP file is
published in name only.

**`.3mf`** slicer projects carry plate arrangement, supports and print
profiles. They are worth more to someone rebuilding the arm than bare STLs,
but they are tied to the slicer and version that wrote them.

The per-link STLs in `../meshes/` are a different thing again: they are
generated by `urdf_extract` for the simulation, one per link in its own local
frame, and are not intended for printing.

## Size and Git

Fusion archives run around 5 MB. That is comfortably inside GitHub's limits
(100 MB per file), so **Git LFS is not needed** at this scale, and it would add
install friction and bandwidth quotas for nothing.

The thing to watch: binary files store a whole new blob per commit, so
iterating the CAD costs ~5 MB a save. If this directory starts dominating
clone times, that is the moment to move it to LFS — retrofittable, just
fiddly. Until then, plain Git is the simpler answer.

`.gitattributes` marks these extensions binary so Git does not attempt to diff
or merge them.

## Before publishing

This arm is derived from the S100/SO-101 design. Check what the upstream
licence requires — attribution at minimum is common for open hardware — before
the CAD goes public. Licence terms are considerably harder to walk back once
files are pushed.
